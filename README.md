# Cofa Project Brain — 공개 하네스 (한국어 대화 버전)

시간 제한 개발 과제용 재사용 하네스입니다. **모든 에이전트가 사용자와 한국어로 대화**하며, 중요한 설계 전에 선택지·제약·반례를 탐색하고, 실제 코드에 근거해 설명하도록 설계했습니다. 구현은 AI에 맡기고 **설계 결정과 검증은 사용자가 직접 하는 것**이 목표입니다.

> 이 저장소에는 특정 과제의 문제·답안, 비공개 자료, 자격 증명, 외부 전송 자동화가 없습니다. 실제 과제 안내와 현장 규정이 항상 우선합니다.

## 과제와 현장 조건은 따로 알려 줍니다
이 하네스는 과제 내용, 제한 시간, 제공 도구를 가정하지 않습니다. 현장에서 확인한 조건(마감, 제출 형식, 쓸 수 있는 AI·도구, 금지 사항)을 첫 프롬프트에 적어 주면 에이전트가 `docs/PROJECT_STATE.md`에 옮겨 적고 그것을 따릅니다. 허용 여부를 모르는 행동(외부 전송, 다른 AI 연결, 브라우저 자동 조작, `git push`)은 에이전트가 하기 전에 묻습니다.

## 설치 (허용된 터미널에서)

작업 폴더에서 두 줄이면 됩니다. 하네스는 작업 폴더 밖(`/tmp/b`)에 받아야 저장소 전체가 제출물에 섞이지 않습니다. `bootstrap.sh`는 인자가 없으면 현재 폴더에 설치합니다.

```bash
git clone https://github.com/Keeweon-Choi/cofa-project-brain /tmp/b
bash /tmp/b/bootstrap.sh
```

`bootstrap.sh`는 없는 `AGENTS.md`·Skill과 `docs/PROJECT_STATE.md`만 추가합니다. 기존 파일을 덮어쓰거나, MCP를 등록하거나, 제공된 도구를 업데이트하지 않습니다. **작업 폴더에 이미 `AGENTS.md`가 있으면** 하네스 규칙을 `docs/COFA_AGENTS.md`로 넣고 안내만 출력합니다. 이때는 기존 `AGENTS.md` 끝에 `docs/COFA_AGENTS.md 도 따른다.` 한 줄을 직접 추가하세요(과제 지침이 우선). 에이전트는 작업 폴더에서 시작해야 합니다.

## 시작 전에 확인할 것
1. 공개 저장소 `git clone`이 허용되는지, `bootstrap.sh`가 `ADDED`를 출력하는지.
2. 제공된 AI 도구의 모델·권한·사용량 한도(Codex라면 `/status`).
3. 에이전트에게 "AGENTS.md 0-1절을 세 줄로 요약해줘"라고 요청해 규칙을 읽는지.
4. Skill이 자동 인식되는지(안 되면 에이전트가 `.agents/skills/<name>/SKILL.md`를 직접 읽게 하면 됩니다).
5. `git --version`, `node --version`, `python3 --version`.
6. 결과 화면을 확인하는 방법. 원격 미리보기라면 서버를 `0.0.0.0`에 띄워야 열립니다.

## 사용법 (간략)
1. `START_HERE.md` 0번: 과제 원문을 **먼저 직접 읽고** 내 이해와 주장 후보를 적습니다. 현장 조건도 아는 만큼 적습니다.
2. 1번 **정의**, 2번 **치명 가정 확인**: 구현 전에, 주장을 통째로 무너뜨릴 가정부터 확인합니다. 모호한 업무 맥락은 현장 문의 창구에 묻습니다.
3. 3번 **한 번 끝까지**: 가장 단순한 방법으로 기준과 비교한 숫자까지 잇고, 검사 명령으로 다시 돌릴 수 있게 합니다.
4. 4번 **약한 고리 보강**을 반복합니다. 실험 전에 내 예측을 적고, 결정은 내가 고르고 이유는 내 말로 남깁니다.
5. 5번 **판단**: 절반쯤과 고비마다 유지/수정/전환/마무리를 정합니다. 구조가 복잡하면 **Architecture Lead 프롬프트**로 두 번째 세션을 엽니다(선택).
6. 6번 **마무리**: 새 기능을 멈추고 흐름·요약·재실행을 확인한 뒤 제출합니다.

단계별 운영과 참고용 시간 비율: [`DEVELOPMENT_LOOP.md`](DEVELOPMENT_LOOP.md). 현장 규정을 다루는 방식: [`AGENTS.md`](AGENTS.md) 0-1절.

## 문서와 Skill
- `templates/PRD.md`, `SRS.md`, `SDD.md`: **과제 내용이 없는 양식**입니다. 실제 문제를 받은 후 필요할 때만 작성합니다.
- `DECISIONS.md`: 결정 시점의 이유·근거를 남기며 사후 합리화를 금지합니다. 내가 쓴 이유는 원문 그대로 남깁니다.
- `VERIFICATION.md`: 실행한 검증의 사실과 미검증 사항을 나눕니다.
- `PROJECT_STATE.md`: 현장 조건, 실제 흐름, 검증 상태, 문제 해결 기록, 남은 한계를 한 파일에 둡니다.
- `.agents/skills/`: 과제 분류, 설계 대안 탐색, 구현 리드, 데이터·제약 감사, 독립 반례 검토, 아키텍처 맵, 검증 등 8개 선택형 절차입니다. **항상 전부 실행하지 않습니다.**

## 선택 도구 / 금지 사항
- 기본은 내장 셸, `rg`, 기존 테스트 러너만 사용합니다. 시간 제한 과제에서는 이것으로 충분합니다.
- Graphify·Serena 같은 코드 탐색 도구는 현장 규정이 허용하고 바로 동작이 확인된 경우에만, LLM 백엔드를 끈 상태로 씁니다.
- **Mermaid**: 실제 코드로 확인한 구조/흐름의 텍스트 시각화. MCP 불필요.
- `MCP_POLICY.md`, `HOOKS_OPTIONAL.md`를 우선 읽으세요. 현장 규정이 금지한 것(다른 AI·모델 연결, 화면 자동 조작, 외부 전송 등)을 위반하지 않도록 합니다.
- 제공된 도구 버전을 업데이트하지 마세요. 네이티브 스킬 로드/훅/MCP는 제공된 버전에 따라 달라질 수 있습니다.
