# Cofa Project Brain — 공개 하네스 (한국어 대화 버전)

3시간 제한 개발 과제용 재사용 하네스입니다. **모든 에이전트가 사용자와 한국어로 대화**하며, 중요한 설계 전에 선택지·제약·반례를 탐색하고, 실제 코드에 근거해 설명하도록 설계했습니다. 구현은 AI에 맡기고 **설계 결정과 검증은 사용자가 직접 하는 것**이 목표입니다.

> 이 저장소에는 시험 문제의 완성된 답안, 비공개 자료, 자격 증명, 외부 전송 자동화가 포함되지 않습니다. 실제 시험 가이드와 과제별 지침이 항상 우선합니다.

## 공개 저장소에 올릴 것
압축파일을 풀어 **숨김 폴더 `.agents`를 포함한 전체 내용**을 공개 GitHub 저장소에 올리면 됩니다. 시험 결과 발표 전까지 공개 상태 유지 등 주최 측 규정을 확인하세요.

올리지 말 것: 시험 문제·데이터, 이전 회차 과제의 문제·코드·결과물, 토큰·키, 특정 과제의 해법 코드.

## 시험 환경에서 설치 (허용된 터미널 사용)

하네스는 **작업 폴더 밖**에 받습니다. 작업 폴더 안에 받으면 저장소 전체가 제출물에 섞입니다.

```bash
git clone https://github.com/Keeweon-Choi/cofa-project-brain.git ~/cofa-project-brain
cd /path/to/TASK_WORKSPACE
bash ~/cofa-project-brain/bootstrap.sh "$PWD"
```

`bootstrap.sh`는 없는 `AGENTS.md`·Skill과 `docs/PROJECT_STATE.md`만 추가합니다. 기존 파일을 덮어쓰거나, MCP를 등록하거나, Codex를 업데이트하지 않습니다. **작업 폴더에 이미 `AGENTS.md`가 있으면** 하네스 규칙을 `docs/COFA_AGENTS.md`로 넣고 안내만 출력합니다. 이때는 기존 `AGENTS.md` 끝에 `docs/COFA_AGENTS.md 도 따른다.` 한 줄을 직접 추가하세요(과제 지침이 우선). 작업 폴더에서 Codex를 시작해야 합니다.

## 사전 체험(1회·15분)에서 꼭 확인할 것
1. 위 `git clone`이 되는지, `bootstrap.sh`가 `ADDED`를 출력하는지.
2. `codex` → `/status`로 모델·권한을 확인. `/model`에서 Astra가 아닌 권장 모델을 고르는 방법.
3. Codex에게 "AGENTS.md 0-1절을 세 줄로 요약해줘"라고 요청해 규칙을 읽는지 확인.
4. Skill이 자동 인식되는지(안 되면 Codex가 `.agents/skills/<name>/SKILL.md`를 직접 읽게 하면 됩니다).
5. `git --version`, `node --version`, `python3 --version`.
6. 서버를 `0.0.0.0`에 띄우고 왼쪽 Browser 도구에서 포트·경로로 열리는지.

## 사용법 (간략)
1. `START_HERE.md` 0번: 과제 원문을 **먼저 직접 읽고** 내 말로 3줄을 적습니다.
2. 1번 **Implementation Sol 시작 프롬프트**로 문제·제약·대안·최소 구현안을 한국어로 받습니다. 모호한 업무 맥락은 메신저의 실무자 에이전트에게 묻습니다.
3. Sol이 최소 수직 기능을 만들고 실제 테스트를 시작하게 둡니다. 결정은 내가 고르고, 이유는 내 말로 남깁니다.
4. 기능을 통합하면 필요할 때 4번 **흐름 확인 프롬프트**로 내가 이해한 흐름과 실제 코드를 맞춰 봅니다.
5. 구조가 복잡하면 2번 **Architecture Sol 프롬프트**로 두 번째 세션을 엽니다. 소규모 과제라면 생략합니다.
6. 160분쯤 새 기능을 멈추고 5번 **제출 전 점검 프롬프트**로 문서·검증 상태를 맞춘 뒤, 170분쯤 제출을 시작합니다.

상세 운영 시간표: [`DEVELOPMENT_LOOP.md`](DEVELOPMENT_LOOP.md). 시험 규정 요약: [`AGENTS.md`](AGENTS.md) 0-1절.

## 문서와 Skill
- `templates/PRD.md`, `SRS.md`, `SDD.md`: **과제 내용이 없는 양식**입니다. 실제 문제를 받은 후 필요할 때만 작성합니다.
- `DECISIONS.md`: 결정 시점의 이유·근거를 남기며 사후 합리화를 금지합니다. 내가 쓴 이유는 원문 그대로 남깁니다.
- `VERIFICATION.md`: 실행한 검증의 사실과 미검증 사항을 나눕니다.
- `PROJECT_STATE.md`: 실제 흐름, 검증 상태, 문제 해결 기록, 남은 한계를 한 파일에 둡니다.
- `.agents/skills/`: 과제 분류, 설계 대안 탐색, 구현 리드, 데이터·제약 감사, 독립 반례 검토, 아키텍처 맵, 검증 등 8개 선택형 절차입니다. **항상 전부 실행하지 않습니다.**

## 선택 도구 / 금지 사항
- 기본은 내장 셸, `rg`, 기존 테스트 러너만 사용합니다. 3시간 과제에서는 이것으로 충분합니다.
- Graphify·Serena 같은 코드 탐색 도구는 사전 체험에서 바로 동작이 확인된 경우에만, LLM 백엔드를 끈 상태로 씁니다.
- **Mermaid**: 실제 코드로 확인한 구조/흐름의 텍스트 시각화. MCP 불필요.
- `MCP_POLICY.md`, `HOOKS_OPTIONAL.md`를 우선 읽으세요. Astra 사용, 외부 AI·모델 연결, Computer Use, 외부 전송, Git Push 등의 금지사항을 위반하지 않도록 합니다.
- 제공된 Codex 버전을 업데이트하지 마세요. 네이티브 스킬 로드/훅/MCP는 고정 시험 버전에 따라 달라질 수 있습니다.
